## Цель работы

Цель лабораторной работы — спроектировать и задокументировать API BookBox, уточнить модель данных, проверить контракт через Mock-сервер, а также спроектировать MCP-сервер и инфраструктуру проекта. Для группы 11 методичка предусматривает выполнение заданий 1–5; задание 6 также описывает инфраструктуру и развёртывание проекта. На первом этапе команда выполняет задания 1–4.

Входными данными служат требования, пользовательские истории, варианты использования и модели процессов из [ЛР3](lab3.md). Подробные материалы текущего этапа собраны в [каталоге ЛР4](lab4/README.md).

## 1. Модель требований и реестр вариантов использования

Для определения объёма API использованы роли и сценарии BookBox из ЛР3. Модель связывает действующих лиц, пользовательские истории и варианты использования, а затем сопоставляет их с требованиями к API. Для проверки полноты операций учтена [CRUD-модель управления каталогом интернет-магазина GetAnalyst](https://getanalyst.ru/database/CRUD-2).

В модель включены роли гостя, покупателя, администратора, аналитика и платёжного провайдера. Истории US-01–US-10 взяты из ЛР3. Добавлены US-11–US-14 для регистрации и входа, управления корзиной и избранным, отзывов, истории заказов и уведомлений.

Составлен реестр из 12 требований API и 14 вариантов использования. Он охватывает каталог и поиск, аккаунты, корзину, избранное, заказ и оплату, предзаказ, уведомления, отзывы, административные действия и аналитику. Отдельно зафиксированы правила доступа: покупатель видит только собственные данные, административные действия требуют соответствующей роли, а повторные команды оплаты и передачи заказа должны обрабатываться безопасно.

Результат: [модель требований и реестр Use Case](lab4/requirements.md). Материал добавлен в навигацию документации проекта и в локальные страницы Wiki.

## 2. Логическая и физическая модели базы данных

Логическая модель уточняет предметную модель ЛР3 для выбранных API-сценариев. В неё входят 18 сущностей, включая аккаунты и роли, каталог книг и справочников, корзину и избранное, заказы и позиции заказа, попытки оплаты, предзаказы, отзывы и уведомления.

Для физической схемы выбрана PostgreSQL 13+ как предварительное проектное решение. В модели заданы первичные и внешние ключи, уникальность email и связей, ограничения количества и денежных значений, статусы заказов, платежей и отзывов, а также индексы для чтения заказов, отзывов и уведомлений. Позиция заказа хранит цену на момент покупки; попытки оплаты имеют ключ идемпотентности.

Подготовлены [логическая модель](lab4/logical-model.md), [физическая ER-модель](lab4/physical-model.md), её [исходник PlantUML](lab4/physical-model.puml) и [SQL-схема PostgreSQL](lab4/schema.sql). SQL-файл описывает создание структуры пустой базы данных и не требует наличия приложения. В рамках текущего этапа PostgreSQL не разворачивался, а SQL не выполнялся.

Выбор PostgreSQL нужно подтвердить при интеграции с BookBox-Server. Репозиторий сервера пока содержит только README, поэтому совместимость схемы с ORM и кодом backend ещё не проверена.
