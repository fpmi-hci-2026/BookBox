# Сценарии вариантов использования BookBox

Пять сценариев соответствуют диаграмме [UC-01–UC-05](../../images/lab3/task4/use-cases.svg). Сценарии используют структуру из [руководства по Use Case](https://systems.education/functional_requirements_in_usecases). Переходы альтернатив привязаны к шагам основного сценария.

## UC-01. Найти учебник

**Актор и платформа.** Покупатель, мобильное приложение. **История.** US-01.  
**Предусловие.** Каталог доступен. **Триггер.** Покупатель открывает поиск с главной или из каталога.

1. Покупатель вводит название учебника и указывает максимальную цену.
2. Приложение передаёт запрос и фильтр цены серверу.
3. Сервер подбирает книги, соответствующие запросу и пределу цены.
4. Приложение показывает название, автора, цену и наличие каждой найденной книги.

**3а. Нет совпадений.** Приложение показывает пустую выдачу и предлагает изменить запрос либо снять фильтр. Покупатель может вернуться к шагу 1.  
**Результат.** Пользователь получает подходящие книги либо понимает, как изменить поиск.

## UC-02. Оформить и оплатить заказ

**Акторы и платформа.** Покупатель, веб-клиент, внешний платёжный сервис. **Истории.** US-02, US-06, US-07.  
**Предусловие.** Покупатель вошёл, в корзине есть хотя бы одна книга. **Триггер.** Покупатель переходит к оформлению.

1. Покупатель указывает адрес и способ доставки. При подарочном заказе добавляет данные получателя и выбирает упаковку.
2. BookBox проверяет наличие и показывает итог с доставкой и выбранной упаковкой.
3. Покупатель подтверждает онлайн-оплату.
4. BookBox передаёт сумму и идентификатор попытки в платёжный сервис.
5. После подтверждения платежа BookBox фиксирует оплату, подтверждает заказ и показывает его номер.

**2а. Недостаточно экземпляров.** Система перечисляет недоступные позиции, и покупатель возвращается в корзину. Запрос списания не отправляется.  
**4а. Платёж отклонён.** Система сохраняет данные и показывает ошибку. Покупатель повторяет шаг 3 с новой попыткой для того же заказа или выходит из оформления.  
**Результат.** При успехе подтверждён один заказ. При отказе данные доступны для повтора.

## UC-03. Оформить предзаказ

**Актор и платформа.** Покупатель, веб-сайт. **Истории.** US-03, US-09.  
**Предусловие.** Покупатель вошёл и открыл карточку временно отсутствующего издания. **Триггер.** Выбрано действие «Предзаказ».

1. BookBox показывает форму и ожидаемый срок, если он известен.
2. Покупатель подтверждает заявку.
3. BookBox повторно проверяет возможность предзаказа и сохраняет заявку со статусом «Ожидает поступления».
4. BookBox показывает номер предзаказа и ожидаемый срок, если он известен.

**3а. Возможность предзаказа отключена.** Система показывает актуальное состояние книги и завершает сценарий без создания заявки.  
**Результат.** Покупатель видит подтверждённый предзаказ или причину отказа.

## UC-04. Добавить книгу

**Актор и платформа.** Администратор, веб-админ-панель. **История.** US-04.  
**Предусловие.** Пользователь вошёл с правом управления каталогом. **Триггер.** Администратор открывает форму новой книги.

1. Администратор вводит название, автора, издательство и цену.
2. Система проверяет доступ и обязательные поля.
3. Система сохраняет карточку.
4. Система подтверждает публикацию книги в каталоге.

**2а. Поля некорректны.** Система показывает ошибку рядом с полем, сохраняет введённые значения в форме и возвращает к шагу 1.  
**2б. Доступ отозван.** Система отклоняет запрос. Карточка не создаётся.  
**Результат.** При успехе книгу можно найти по названию.

## UC-05. Посмотреть статистику продаж

**Актор и платформа.** Аналитик, веб-админ-панель. **Истории.** US-05, US-10.  
**Предусловие.** Аналитик вошёл с доступом к отчёту. **Триггер.** Аналитик выбирает период.

1. Интерфейс отправляет период серверу.
2. Сервер проверяет доступ и границы периода.
3. Сервер агрегирует подтверждённые заказы за период и продажи по книгам.
4. Интерфейс показывает сумму, число заказов и список популярных книг.

**2а. Период задан неверно.** Интерфейс просит исправить даты и возвращает к выбору периода.  
**2б. Доступ отозван.** Сервер отклоняет запрос без выдачи данных.  
**3а. Нет подходящих заказов.** Интерфейс показывает сообщение об отсутствии данных.  
**Результат.** Аналитик получает сводку за указанный период или объяснение пустого результата.
