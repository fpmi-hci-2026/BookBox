# Применение навыка GetAnalyst к BookBox

Из папки методички изучены примеры MedAssistGA, REST API библиотеки ElibraGA, интеграционных User Stories, PlantUML Sequence и набор навыков аналитика. Из примеров взяты структура спецификации с границами системы и сценариями, проверка доступов и ошибок API, привязка критериев к цели пользователя и явное разделение запросов, ответов и альтернатив в sequence-диаграммах. [Материалы GetAnalyst](https://disk.yandex.ru/d/LUX0-q4ClFEC6A)

## Вход и ход работы

ИИ-агент применил инструкции из `getanalyst-database-designer-SKILL.zip`, включая справочник стандартов. Выбран режим узкой задачи для пересмотра логической модели и построения ERD. Использованы объектные модели ЛР1 §12 и ЛР2 §5, классы заказа из задания 2 и сценарии UC-01–UC-05. Исходная постановка сохранена в [промпте ERD](prompts/erd.md).

| Шаг навыка | Что получилось в BookBox |
|---|---|
| Восстановить жизненный цикл и границы | Выделены каталог, покупка и предзаказ. Резервирование и правила возврата вынесены в вопросы к спецификации. |
| Проверить кардинальности | Связь заказов с книгами разложена через позиции заказа. Авторы и жанры связаны с книгой через таблицы связей. |
| Выделить исторические значения | Цена единицы и адрес заказа сохраняются при оформлении. Дата подтверждения отделяет продажи от незавершённых заказов. |
| Проверить целостность и повторы | Попытки оплаты получили собственный идентификатор, ссылка платёжного сервиса уникальна при её наличии. Повтор запроса той же попытки использует тот же идентификатор, новый платёж после отказа получает новый. |
| Сверить артефакты | Модель оплаты сопоставлена с UC-02, FR-04 и диаграммой последовательности. Тип денег указан как Decimal. |

Результат применения — согласованная логическая ERD в [каталоге диаграмм](diagrams.md), дополненные правила работы с данными в [спецификации](specification.md) и решение оставить СУБД, DDL и правила миграций до выбора реализации.
